The route

Nine deep-linkable groups instead of one page with five tabs. Branding holds themes; a theme is a row, not a column on every surface.

After

The route, and the three tests

A setting is global unless it fails one of these. Not judgement, tests you can run against the schema.

What the widget row stores

/app/widgets/:templateKey shop_widgets   template_id, category, slug, position   custom_settings     style_variant layout fact     promo_line copy   Brand_Primary / Secondary / Accent   Widget_Background / Product_Tile   corners / font_size / surface_style   17 selling settings

The tests

1 the enum DIFFERS per template    => per template    default_intent sub: subscribe|onetime    master: auto|subscribe|bundle|onetime 2 it is COPY    => per placement    promo_line, tab_label_*, policy_link_label 3 it is a LAYOUT FACT of the placement    => per placement    style_variant, hide_product_row,    summary_expanded_by_default otherwise => global

Absent, not disabled, is already your rule. withoutFields() in widget-templates.ts drops a control when a template is structurally unable to honour it, and the comment beside it says a control that changes nothing is worse than an absent one. That is what makes global safe: the store holds the value, the template decides whether a control appears.

What is left open

Three things this design does not settle, each of which changes code.

Named in the schema, contradictory

1 Product_Tile    schema title "Body Text" => --sb-text    themer label "Product tile colour"    the real tile is Product_Tile_Background,    absent from subscription widgets 2 --sb-border = #c4c4c4, hardcoded    themer says borders adapt. they do not 3 corners_custom_pct    admin renders a % suffix,    code reads it as PIXELS

Decisions this needs from you

a does the PORTAL join the theme?    it has its own 3 colours today    primary_brand / button / button_text b does MASTER keep theme.* or move    to the flat Brand_* schema?    two schemas is the real duplication now c can a SECTION pick a theme,    or does it always take the page's?    drawn here as always the page's

(b) is the one that matters. Until master and the six subscription widgets share one styling schema, Branding has to write two shapes and a merchant setting one theme still gets two behaviours. Everything else here works either way.
