# StackBack admin screens — real Polaris web components

These are the create/manage admin screens rebuilt on Shopify's **Polaris web components**
(`<script src="https://cdn.shopify.com/shopifycloud/polaris.js">`), for pixel-accurate
Polaris fidelity, replacing the earlier hand-rolled-CSS wireframes in the parent folder.

## How to view
The Polaris CDN script only runs over **HTTP**, not `file://` (a double-clicked file will
render blank because the script is treated as a static snapshot). To view:

```
cd "Project Deliverables/stackback/merchant/Polaris"
python3 -m http.server 8791
# then open http://localhost:8791/PlanSetup_Polaris_v2.html or BundleSetup_Polaris_v2.html
```

In the real embedded Shopify app this renders natively (no server needed); the HTTP step is
only for previewing the standalone wireframe.

## What is real Polaris vs custom
- **Real Polaris web components:** page shell + right sidebar (`s-page` + `aside` slot),
  cards (`s-section`), text fields (`s-text-field`), badges (`s-badge`), switch (`s-switch`),
  select (`s-select`), buttons (`s-button`), links (`s-link`), layout (`s-stack`, `s-box`).
- **Custom, styled to match Polaris** (kept from the locked designs per Sumant's steer):
  the segmented pills (Apply to / Schedule / Checkout), payment multi-select chips, the
  "More options" disclosure, the top contextual save bar (the real one is App Bridge
  `ui-save-bar` at build time), and the storefront widget preview (brand tokens, per the
  two-palette rule).
- The left Shopify **global nav** is mock chrome (the real Shopify admin renders it around
  the embedded app iframe; it is not part of the app's own markup).

## Notes for dev
- Amount-off discount type and the single per-plan shipping override are design deviations
  from the current code model; both need backend confirmation (see state.md open questions).
- Status badge: Polaris pushes `secondary-actions` into a header overflow menu, so the
  "Not live yet" capsule sits at the top of the content rather than inline beside the title.
